# 操作纪律

每次会话开始，按顺序读：本文件 → `STATE.md` → `runs/` 下最新一条 `record.md`。总行数不超过 300。

1. 图片不进主上下文。看图派子 agent，只回传不超过 150 字的结构化判定。
2. 日志只 grep 不整读。输出重定向到 `runs/E0NN/error.log`，grep `Error|Traceback|OOM|CUDA`。
3. 工作流 JSON 不整读，只读本轮要改的节点。
4. 一次会话只做一个实验。做到第三个实验必须停下。
5. 每轮必须写回。收场更新 `STATE.md` 的版本号、新结论、下一件事。
6. 只信文件不信记忆。不说"你还记得吗"，只说"读 STATE.md"。
7. 上下文不够就先写回再换会话，不许硬撑。
8. 不确定就问，不盲目决策。

会话结束前必须执行收场四件事：写 `record.md`、追加 `LESSONS.md`、更新 `STATE.md`、只回三行摘要。

## 每轮结束先做上下文健康检查

命中任意一条即交接，不再继续推理：

- 本会话已完成 2 个任务
- 累计读取超过 10 个文件或 1500 行
- 出现系统压缩历史的提示
- 需要回看更早内容才能继续
- 开始复述旧结论、忘记已确认参数、编造路径或哈希

交接顺序：写 `record.md` → 写交接块 → 更新 `STATE.md` → 更新 `LESSONS.md` → 输出重启指令 → 停止。

## 压缩契约

压缩是移动，不是删除。被压掉的信息必须留下路径与锚点。

- 必须保留：用户原话约束、全部数值与哈希、已证实结论、否定性结论、未决问题、下一步、决策理由
- 可以丢弃：命令完整输出、报错堆栈细节、已落盘的中间推理、看过的图片、重复寒暄
- 绝不改写：数字、哈希、文件名、用户原话

审计四问（当前版本 / 三条结论 / 未决问题 / 下一步）必须都能指出文件出处。指不出就是丢了，回去补。

## 决策分级

- A 可逆、低成本、不影响基线 → 直接做，记录一句
- B 会改基线或占用大量 GPU 时间 → 给方案 + 推荐 + 代价，等确认
- C 删数据、换模型、改评分卡、变方向、对外发布 → 必须等明确同意

用户说"不懂"时，改为给三段式方向（为什么重要 / 最小一步 / 怎么判断对）+ 一个默认建议。
