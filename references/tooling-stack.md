# 工具栈

按"能长期跑下去"挑选，不按"能装多少"挑选。分期上线，每一期都要先跑满 20 次实验再接下一期。

## 分期

### 阶段一：可复现

| 工具 | 作用 | 关键用法 |
|---|---|---|
| DVC | 图片与模型的版本控制 | `dvc add runs/E0NN/out`，git 只提交 `.dvc` 指针 |
| ComfyUI-Manager 快照 | 防止节点升级后老工作流打不开 | 每次晋级 `vNN.json` 时同时存一份 `env-vNN.json` |
| comfy-cli | 环境与跑批的命令行入口 | `comfy run --workflow workflows/vNN.json --wait` |

这一期不改变工作习惯，只补"可复现"。最不该省的是 DVC：图、模型、参数三者不绑定，历史就永远复现不出来。

### 阶段二：可对比

| 工具 | 作用 | 关键用法 |
|---|---|---|
| MLflow | 参数、指标、产出的实验库 | `log_params` / `log_metrics` / `log_artifact` |

跑满 20 次实验再接。少于这个量，"记参数"只是负担。接入后用平行坐标图看哪个参数真正影响分数——这件事用 Markdown 表格永远做不到。

### 阶段三：可扩展

| 工具 | 作用 | 触发条件 |
|---|---|---|
| FiftyOne | 浏览、聚类、去重、筛选海量历史图 | 图片超过 2000 张 |
| Optuna | 参数空间搜索 | 已明确想搜最优区间，且能接受每 trial 跑 5 个种子 |
| Label Studio | 把评分卡做成 Web 标注界面 | 评估者超过一人，或想训练自有打分模型 |

Optuna 的硬约束：每个 trial 必须跑 3-5 个固定种子取均值，否则扩散模型的随机性会淹没搜索信号。

## 分工

- MLflow 记"发生过什么"（参数、分数、产出）
- DVC 记"当时用了什么"（图、模型、版本）
- 环境快照保证"现在还能不能跑"

`STATE.md` 里贴 MLflow 的 run id 即可，不重复存这些内容。**人读结论，机器读 MLflow。**

## 不推荐

| 工具 | 原因 |
|---|---|
| n8n | 面向生产流水线，不是研发实验；调试成本会让实验变慢 |
| Label Studio（单人就上） | 需要跑服务端和备份数据库，五项指标的收益不抵运维成本 |
| 自建 Web 看板 | 在超过 500 次实验之前，Markdown 加 CSV 足够 |

## 版本钉死

长期项目最容易死在这里：同名 checkpoint 被覆盖更新，两周前的记录再也复现不出来。

`STATE.md` 里记录模型文件的**哈希**，不只记名字。每次更换模型文件都要更新哈希并开一个新版本号。
