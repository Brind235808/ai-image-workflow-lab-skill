# 上下文交接与重启

长会话后期，模型开始复述旧结论、忘记已确认的参数、把两次实验混在一起。这时产出的记录会污染基线，比不做更糟。**提前交接是质量措施，不是性能措施。**

## 为什么不能靠感觉

agent 无法精确读取剩余 token。所以用可观测的代理信号，不猜百分比。

## 触发阈值

每轮任务结束做一次检查，命中任意一条即交接：

| 信号 | 说明 |
|---|---|
| 本会话已完成 2 个任务 | 默认上限，第三个任务必须在新会话 |
| 累计读取超过 10 个文件或 1500 行 | 读了大量原始材料 |
| 出现系统压缩历史的提示 | 已经进入被压缩状态，结论开始不可靠 |
| 需要回看更早内容才能继续 | 说明工作记忆已失效 |
| 复述旧结论、忘记已确认参数 | 退化征象 |
| 编造路径、哈希或参数 | 严重退化，立即停止 |

任一命中，**不再做任何后续推理**。

## 交接五步

按顺序执行，不许跳步：

1. **写 `record.md`**，用固定六段格式（假设/改动/参数/结果/判定/下一步）。
2. **写交接块**，附在 `record.md` 末尾：

```
## 交接
当前版本: v05
本轮改动: cfg 7 -> 6
结果: 平均分 7.2 -> 7.8，手部缺陷率 30% -> 15%
未决: 文字乱码未改善，怀疑是负面词缺失
下一件事: 在 v06 加 text/watermark 负面词，跑 E013
```

3. **更新 `STATE.md`**：版本号、最优参数、未解决问题、下一件事。
4. **更新 `LESSONS.md`**（若本轮有可复现结论）。
5. **输出重启指令**，然后停止。

## 重启指令模板

若当前环境能直接开新上下文窗口，调用对应能力并把交接块作为初始摘要。否则把下面这段交给用户，让他新开会话后粘贴：

```
新项目会话。先读 ai-image-lab/AGENTS.md 和 STATE.md，再读 runs/E012/record.md 的交接块。
不要读其他文件，不要读图片。

用 5 行确认你接到的状态：当前版本、已确认结论、未决问题、下一件事、你打算只改哪个参数。
然后等我指令。
```

## 交接时必须写进文件的话术

不要只在对话里说"上下文快满了，建议新开会话"。用户不会替你保留状态。**凡是需要延续的信息，必须在文件里。**

## 禁止

- 在满上下文状态里做总结：总结会失真，且会漏掉关键项。
- 硬撑到输出明显变差再交接：那时写下的记录已经不可信。
- 交接时重新读一遍全部历史：交接的目的就是不再读历史。
- 把交接块写成散文：必须是五个固定字段，能被下个会话直接解析。
