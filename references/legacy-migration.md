# 历史产出复古

## 原则

复古不是编年史，是**提资产**。不要试图把过去每一轮对话、每一张图都补成完整记录——那等于把爆上下文的过程重演一遍。

历史上真正有价值的只有四类：

| 资产 | 来源 | 去向 |
|---|---|---|
| 可复现工作流 | `.json` 文件、图片内嵌元数据 | `workflows/v01.json` |
| 好图（基线/风格锚点） | 历史输出目录 | `refs/anchors/` |
| 踩过的坑 | 报错截图、失败图、随手笔记 | `LESSONS.md` |
| 提示词片段 | 聊天记录、txt | `refs/prompts.md` |

其余全部归为冷存，不读。

## 第一步：只跑脚本，不看图

```
python scripts/inventory.py <历史图片根目录> -o inventory.csv
```

输出列：路径、尺寸、是否有工作流、是否有 API 参数、seed、steps、cfg、sampler、checkpoint、LoRA、提示词片段、`meta_level`。

ComfyUI 的 SaveImage 会把完整参数写进 PNG 的文本块。**先扫元数据，再决定看哪张图**，这一步的 token 成本为零。

## 四个会话，不许合并

**会话 1：跑清单。** 只执行脚本，产出 `inventory.csv` 和一句统计。不聊图，不看图。

**会话 2：提基线。**

```
读 STATE.md 和 inventory.csv（只看 has_api=1 的行）。
按 cfg/step/sampler 分组统计，告诉我哪些参数组合出现最多。
从出现最多的组里挑 5 张候选，列出 path。不要打开任何图片。
```

然后派子 agent 看这 5 张，挑 3 张，用内嵌元数据反解成 `workflows/v01.json`。

**必须做复现验证**：用 v01 加原 seed 重跑，能否近似复现。历史好图常是手工微调出来的，参数不全。复现失败就不能当基线，只能降级为参考图。

**会话 3：提坑。**

```
按失败模式归类这些图的内嵌提示词：手部畸形 / 文字乱码 / 主体错位 / 过曝 / 风格漂移。
每类给一条"避免方法"，写进 LESSONS.md，格式：日期 | 结论 | 证据路径。
```

负面清单比成功经验值钱，这是过去最贵的一笔学费。

**会话 4：定基线 + 评分卡。**

```
读 STATE.md、LESSONS.md、refs/anchors 里 3 张好图和 3 张废图。
用它们给评分卡定标：每项 0 分和 2 分分别长什么样。
写进 STATE.md：五项指标、判定标准、六条锚点图路径。
```

## A/B 分级

`refs.csv` 必须有一列 `meta_level`：

- **A 级**（有完整元数据）：可直接当基线参数，进 `workflows/` 候选。
- **B 级**（无元数据）：只当风格参考图，不做参数反推，不进 `workflows/`。

理由：靠画面猜出来的参数是猜测，不是证据。让它进基线会污染后续全部实验。

## 完成标准

复古结束的标志是产出这三样，而不是"整理完毕"：

1. `workflows/v01.json` 且复现验证通过
2. `LESSONS.md` 至少 10 条带证据的结论
3. 一张定好锚点的评分卡

## 常见翻车

- 想归档全部：`legacy/` 原样留着，只在 `inventory.csv` 留索引。
- 截图和转发过的图没有元数据：只能降级为参考图。
- 一次扫太多盘：先扫最有产出的两三个目录，够建基线就停。
- 在单张图上反复校准超过三轮：边际收益断崖，停下。
