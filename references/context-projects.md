# 上下文与记忆项目

选型只看一条：**会不会替你悄悄删东西。** 会删的，无论多少 star 都不要用来存结论。

## 四类，从最不黑盒到最黑盒

### A 检索式外部记忆（不压缩，按需取）

| 项目 | Star | 说明 |
|---|---|---|
| [basic-memory](https://github.com/basicmachines-co/basic-memory) | 4.3k | 本地 Markdown 笔记 + 检索，人可读、可 diff、无黑盒 |
| [claude-context](https://github.com/zilliztech/claude-context) | 12.6k | 代码库语义检索，按需取片段而不是全量读入 |

安全性最高：不压缩就没有删除。本项目自带的目录约定已经覆盖了它的核心价值，只有在需要跨项目共享笔记时才值得引入。

### B 结构化抽取记忆（schema 可审，抽取不可控）

| 项目 | Star | 黑盒程度 |
|---|---|---|
| [mem0](https://github.com/mem0ai/mem0) | 67.7k | 高。抽取与更新全交给模型，只能配置"存哪类"，不能规定"哪句必须留" |
| [graphiti](https://github.com/getzep/graphiti) | 32.2k | 中。实体与关系 schema 可审，带时间有效性，抽取仍由模型驱动 |
| [letta](https://github.com/letta-ai/letta) | 25.2k | 中。核心记忆块可见可改，但换入换出由模型决定 |
| [langmem](https://github.com/langchain-ai/langmem) | 1.7k | 高。与 mem0 同类 |

共同问题：能审计"最后存了什么"，不能规定"压缩时保留哪句"。适合存事实型信息（角色设定、参数偏好），不适合存结论与否定性结论。

### C 确定性压缩（唯一可以自己规定）

| 项目 | Star | 说明 |
|---|---|---|
| [LLMLingua](https://github.com/microsoft/LLMLingua) | 6.8k | 显式压缩率 + 可指定必须保留的 token，结果可复现 |

边界很关键：它压缩的是**你传给模型的 prompt**，不是 IDE 的对话历史。除非自己搭调用链路，否则用不上。适合压缩长文档与检索结果，不适合压缩实验结论。

### D 平台内建自动压缩

不开放规则接口。不可配置、不可审计、不可回滚。这一层只能靠"不让它触发"来绕开，见 `compression-contract.md`。

## 按场景选

| 你要什么 | 选什么 |
|---|---|
| 不想每次重讲项目背景 | 本 skill 的目录约定，不必上框架 |
| 跨项目共享笔记 | basic-memory |
| 给 agent 长期记住角色、参数、版本 | graphiti（schema 可审） |
| 压缩长文档或检索结果 | LLMLingua |
| 多应用共享记忆、能接受黑盒 | mem0，但只存事实，不存结论 |
| 自建 agent 平台 | letta |

## 明确不推荐

- **mem0 用来存实验结论**：它会在后台改写、合并、遗忘，你无法规定哪条必须留。
- **letta 用在单人项目**：核心价值在于多会话状态机，单人加本地文件已足够。
- **LLMLingua 压缩实验记录**：压缩后的文本不可逆，会丢掉参数与否定性结论。
- **任何"自动总结历史"的插件**：总结就是改写，改写后的结论不可审计。

## 一句话

**结论放文件，事实可以放框架，过程直接丢弃。**
