# 决策协议

目标是：既不因为小事反复打扰用户，也不在关键节点自作主张。

## 分级

| 级别 | 判据 | 例子 | 动作 |
|---|---|---|---|
| A 可自行决定 | 可逆、低成本、不影响基线 | grep 哪个关键词、临时文件放哪、先看哪张图、读哪个字段 | 直接做，记录里写一句 |
| B 先说再做 | 会改基线、占用大量 GPU 时间、影响产出 | 改 cfg、换采样器、批量重跑 20 张、调整 LoRA 权重 | 给 2-3 个方案 + 推荐 + 代价，等确认 |
| C 必须停 | 删数据、换模型或素材、改评分卡、变方向、对外发布 | 删除 runs、替换 checkpoint、改评分维度、发布图包 | 必须等用户明确同意 |

判不准时按高一级处理。

## 提问模板

固定三行，不写长段落：

```
问题：cfg 6 与 7 的差异无法从单张图判断，需要扩大样本。
选项：A 同 seed 重跑 5 张（约 3 分钟）／B 扩大种子集到 10 个（约 6 分钟）／C 先不动，下轮再看。
推荐：B。因为当前差异小于随机波动，5 张不足以区分。
```

禁止：

- 开放式提问："你想怎么做？"
- 只报问题不给选项
- 把专业术语堆在选项里，用户无法判断代价

## 用户表示不懂时

不要继续追问细节，也不要解释一堆原理。切换到"给方向"三段式：

```
为什么重要：这一步决定后面 10 次实验有没有意义。
最小一步：先只改 cfg，跑 5 张，不做其他改动。
怎么判断对：手部畸形从 3/5 降到 1/5 以内，就算对。
默认建议：按这个做，我可以直接开始。
```

最后一定要给出默认建议，让用户可以用一句"就按你说的"推进。

## 决策留痕

- 单次决策 → `record.md` 的"判定"段，写一句理由。
- 跨实验有效的决策 → `LESSONS.md`，带证据路径。
- 方向级决策 → `STATE.md` 的"方向校准"行，带日期。

没有留痕的决策，下个会话会重问一遍，等于没决策。

## 常见错误

- 为了显得高效而在 B 级决策上直接动手：改坏了无法归因。
- 把 C 级决策包装成"建议"：用户点个头就执行，风险仍然存在。
- 用户说"你看着办"就完全放手：仍然要给出选项和推荐，只是把确认权交回用户。
