# 立项分析

只在项目第一次对话做。目的是把"我想要更好的工作流"这种模糊愿望，压成可以逐条验证的东西。

**这一阶段不跑图。**

## 三个产出

### 1. 目标陈述

一句话，必须同时包含三件事：

```
产出是什么 + 给谁看 + 判好的标准
```

反例：「我想提升生图质量。」
正例：「产出一套 12 格的角色剧情图，用于个人发布，标准是角色跨格一致、无文字乱码、画风统一。」

### 2. 验收标准

拆成 3-5 条可观察的条件。每条必须是"看图就能判断"的，不能是感受。

可用维度：主体正确、手部完整、无文字、构图完整、风格与参考一致、跨格角色一致。

反例：「画面更精致。」
正例：「12 格中手部畸形不超过 1 格；画面内不出现任何文字；发色与服装在 12 格中一致。」

### 3. 首批实验队列

`BACKLOG.md` 前三条，每条一个假设、一个唯一变量。第一条通常不是优化，而是**建立基线并验证可复现**。

## 必须问清的六件事

| 问题 | 为什么必须问 |
|---|---|
| 产出形态是什么 | 决定评分卡选哪几项 |
| 成功的样子是什么 | 决定验收标准，否则无法判定晋级 |
| 最怕的失败是什么 | 决定负面清单优先级 |
| 硬件与模型约束 | 决定分辨率、batch、可测参数范围 |
| 手上已有什么资产 | 决定从零开始还是复古提基线 |
| 第一个小实验是什么 | 保证第一次会话就能闭环，避免空转 |

一次问完，不要挤牙膏式追问。

## 写到哪里

- 目标陈述、验收标准 → `STATE.md` 顶部的"方向"段
- 三条实验 → `BACKLOG.md`
- 待确认的约束 → `STATE.md` 的"未解决问题"

## 方向校准

方向不是一次定死，但也不能频繁改。只在两种情况下重看：

1. 连续 3 次实验没有提升
2. 两周没有产生晋级

校准时只回答一个问题：**当前方向还能不能通过参数微调达成验收标准？** 不能的话，是目标太大，还是路径错了。结论写进 `STATE.md` 的"方向校准"行，带上日期。

## 反例

- 立项阶段就开始跑图：没有验收标准，跑出来的结果无法判定好坏，等于白跑。
- 一次列 20 条实验：前 3 条都还没跑完，后面的必然作废。
- 把"参考某个作者"当目标：风格可以借鉴，但验收标准必须写成可观察的图面条件。
