# 实验设计

## 单变量原则

一次实验只改一个维度，其余全部冻结：工作流版本、checkpoint、LoRA、分辨率、种子集、样本数。

可测的维度只有这些，按优先级排列：

1. 提示词结构（固定块与变量块的拆分方式）
2. 采样器与调度器组合
3. 步数
4. CFG
5. LoRA 权重
6. 负面提示词
7. 分辨率与分桶

同时改两个维度，结果无法归因，实验作废。

## 固定样本

- 种子集固定 5 个，写进 `STATE.md`，所有实验共用同一组。
- 每组每个种子出 1 张，共 5 张。
- 提示词固定一组基准用例，不因实验临时更换。

## 评分卡

五项，各 0-2 分，满分 10：

| 项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 主体正确 | 主体缺失或错位 | 主体正确但细节偏离 | 完全符合 |
| 手部 | 明显畸形 | 轻微异常 | 正常 |
| 文字 | 出现乱码文字 | 有模糊字形 | 无文字 |
| 构图 | 构图失衡 | 基本可用 | 构图完整 |
| 风格一致 | 风格漂移 | 部分一致 | 与参考一致 |

**每项必须有锚点图**：把 1-2 张满分图和 0 分图存进 `refs/anchors/`，路径写进 `STATE.md`。没有锚点，两周后你的打分标准会变，历史分数全部不可比。

## 种子决策树

出图不合格时，先判断是哪类问题，再决定动作：

```
同 seed 重跑结果不同        -> 环境/缓存问题，先清缓存，不要调参
同 seed 稳定，换 3-5 个 seed 有合格 -> 随机性问题，继续扫 seed
换 5 个 seed 全不合格        -> 提示词或参数问题，停止扫 seed，进实验
```

这条决策能省掉大量无效重跑。绝大多数"参数不灵"其实是随机性没扫够，或缓存没清。

## 自动指标政策

自动指标（VQAScore、ImageReward、HPSv2、美学分）只有一个用途：**按分数排序，决定先看哪些图**。

禁止用途：

- 用总分决定一张图是否重跑
- 用总分作为晋级的唯一依据
- 用总分比较两个不同题材的提示词

理由：偏好模型有系统性偏置（偏亮、偏饱和、偏中心构图），拿它当裁判会一路收敛到"高分但无聊"。

## 晋级规则

一个改动要升级为新的基线版本，必须同时满足：

1. 平均分高于当前基线
2. 五项中没有一项低于当前基线
3. 回归集（固定的 5 条基准用例）无新增失败

三条都满足才写 `workflows/vNN+1.json` 并更新 `STATE.md`。只满足第一条的，记为"待观察"，不进基线。

## 记录格式

每条 `record.md` 固定六段，不超过 40 行：

```
假设：改 X 会让 Y 变好，因为 Z
改动：v05 -> v05-test01，仅 cfg 7 -> 6
参数：seed=101,102,103,104,105 / steps=28 / sampler=dpmpp_2m
结果：平均分 7.2 -> 7.8；手部缺陷 30% -> 15%；文字仍乱码
判定：晋级 / 待观察 / 放弃（三选一，必须写理由）
下一步：一句话，可执行
```

判定必须三选一，不许写"还行"。
